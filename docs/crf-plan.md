# CRFを用いた点字変換エンジンの設計と実装

## 1. 開発背景と従来のアプローチにおける課題

既存の辞書ベース、あるいはルールベースの形態素解析システムによる点訳には、実用化とメンテナンスの面で以下の3つの大きな課題が存在します。

### ① 文脈による「同字異音語」の読み分け

単純な辞書照合では、単語の周辺状況（文脈）に応じた読みの使い分けが困難です。

* **例1（相撲 vs 天体）：** 「横綱に勝つ**金星**（きんぼし）」 / 「太陽系の**金星**（きんせい）」
* **例2（気配 vs 評判）：** 「**人気**（ひとけ）のない通り」 / 「クラスの**人気**（にんき）者」
これらを判別するには膨大な「if-then」ルールが必要となり、限界があります。

### ② ひらがな連続時の「分かち書き」

点字には、発音のまとまりごとにスペースを空ける「分かち書き」の厳密なルールがあります。

* **課題：** 「はなはななな」のように、ひらがなが連続する場合、どこが単語の境界かを特定するのは辞書だけでは困難です。
* **MLの利点：** 文字の並びの確率（統計）から、最も自然な区切り位置を推論できます。

### ③ 辞書メンテナンスの「職人芸」化と肥大化

* 品詞体系や読みの付与基準が複雑で、辞書の構築・更新に高度な専門知識（職人技）が要求されます。
* 語彙が増えるたびに辞書データが肥大化し、メモリリソースの少ないデバイスでの動作を圧迫します。

---

## 2. 解決策：CRF（条件付き確率場）による推論

本計画では、巨大な辞書を保持する代わりに、**CRF（Conditional Random Fields）**という統計的モデルを採用します。

* **特徴：** 「現在の文字」だけでなく「前後の文字」「文字種」などの特徴量を考慮し、系列全体のラベル（読み・区切り）を最適化します。
* **メリット：** 辞書にない未知語でも、周囲の文脈から「読み」や「区切り」を推測できるため、ロバスト（頑健）な変換が可能です。

## 3. 動作環境 (ターゲットスペック)

軽量な組み込みLinux環境でもストレスなく動作する設計を目指します。

| 項目 | ターゲットスペック | 備考 |
| --- | --- | --- |
| **対象OS** | Linux (Ubuntu, Debian, Yocto, Alpine等) | POSIX準拠環境 |
| **CPU** | ARM Cortex-A シリーズ（1GHz以上推奨） | Raspberry Pi Zeroクラスでも動作可 |
| **RAM (メモリ)** | **32MB以下**（モデル展開時） | 辞書全体を持たないため低消費 |
| **ストレージ** | **5MB 〜 15MB** | 学習済みバイナリモデルのみを配置 |
| **推論速度** | 1文あたり 数ミリ秒 〜 数十ミリ秒 | リアルタイム点訳・TTSへの受け渡しに十分 |

## 4. アーキテクチャとデータ構造

点字（表記維持が必要）とTTS（完全かな化が必要）の共通基盤として、**「リッチ・トークン」**という中間表現を導入します。

### 4.1 リッチ・トークンの定義（Python例）

```python
from dataclasses import dataclass

@dataclass
class RichToken:
    surface: str   # 元の表記（例: "4", "金星"）
    reading: str   # 読み（例: "よ", "きんぼし"）
    tag: str       # 属性（例: "NUM", "NOUN", "PART"）
    is_split: bool # 点字ルール上、直後で分かち書きをするか

```

### 4.2 特徴量抽出のコードサンプル

```python
def extract_features(sentence, i):
    """i番目の文字に対する特徴量を抽出する"""
    char = sentence[i]
    features = {
        'bias': 1.0,
        'char': char,
        'type': get_char_type(char), # 漢字/かな/数字の種別
    }
    # ウィンドウサイズ2（前後2文字）のコンテキストを考慮
    if i > 0:
        features['prev'] = sentence[i-1]
        if i > 1:
            features['2prev'] = sentence[i-2]
    if i < len(sentence) - 1:
        features['next'] = sentence[i+1]
        if i < len(sentence) - 2:
            features['2next'] = sentence[i+2]
            
    return features

```

## 5. 開発ロードマップ

1. **データ生成 (Phase 1):** Sudachi等の既存ツールを用いて「漢字文章」から「読み・分かち書きタグ」のペアを自動生成。手動で微調整を行い、教師データを作成。
2. **モデル学習 (Phase 2):** `sklearn-crfsuite` を用いて学習。点字特有の例外ルール（助詞の「は→ワ」等）が重みに反映されるよう調整。
3. **モデル圧縮とC++化 (Phase 3):** 学習した重みを `libcrfsuite` 等で読み込める形式に書き出し、組み込みデバイス用のC++推論エンジンを実装。
4. **フォーマッター実装 (Phase 4):** リッチ・トークンを元に、「点字文字列（数符付き）」と「TTS用かな文字列」を生成する出力層を作成。
