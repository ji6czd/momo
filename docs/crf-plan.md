# CRFを用いた点字変換エンジンの設計と実装

## 1. 開発背景と従来のアプローチにおける課題

既存の辞書ベース、あるいはルールベースの形態素解析システムによる点訳には、実用化とメンテナンスの面で以下の3つの大きな課題が存在します。

### ① 文脈による「同字異音語」の読み分け

単純な辞書照合では、単語の周辺状況（文脈）に応じた読みの使い分けが困難です。

- **例1（相撲 vs 天体）：** 「横綱に勝つ**金星**（きんぼし）」 / 「太陽系の**金星**（きんせい）」
- **例2（気配 vs 評判）：** 「**人気**（ひとけ）のない通り」 / 「クラスの**人気**（にんき）者」
  これらを判別するには膨大な「if-then」ルールが必要となり、限界があります。

### ② ひらがな連続時の「分かち書き」

点字には、発音のまとまりごとにスペースを空ける「分かち書き」の厳密なルールがあります。

- **課題：** 「はなはななな」のように、ひらがなが連続する場合、どこが単語の境界かを特定するのは辞書だけでは困難です。
- **MLの利点：** 文字の並びの確率（統計）から、最も自然な区切り位置を推論できます。

### ③ 辞書メンテナンスの「職人芸」化と肥大化

- 品詞体系や読みの付与基準が複雑で、辞書の構築・更新に高度な専門知識（職人技）が要求されます。
- 語彙が増えるたびに辞書データが肥大化し、メモリリソースの少ないデバイスでの動作を圧迫します。

---

## 2. 解決策：CRF（条件付き確率場）による推論

本計画では、巨大な辞書を保持する代わりに、**CRF（Conditional Random Fields）**という統計的モデルを採用します。

- **特徴：** 「現在の文字」だけでなく「前後の文字」「文字種」などの特徴量を考慮し、系列全体のラベル（読み・区切り）を最適化します。
- **メリット：** 訓練データで学習した読みの候補から、周囲の文脈に基づいて最適なものを選択できるため、ルールベースでは困難な同字異音語の判別や分かち書き判定が可能です。

---

## 3. CRFとは

### 3.1 CRFの基本概念

**CRF（Conditional Random Fields：条件付き確率場）**は、系列データのラベリング問題に特化した機械学習手法です。

#### 手法の特徴

- **系列全体を考慮した最適化：** 1文字ずつ独立に判定するのではなく、文全体の文脈を考慮して、最も確からしいラベル系列を選択します。
- **局所的な特徴量の活用：** 各位置における「文字」「文字種」「前後の文字」などの特徴量を組み合わせて判定します。
- **確率的モデル：** 訓練データから統計的パターンを学習し、未知の入力に対しても柔軟に対応できます。

#### 数学的な定義（簡略版）

入力系列 $X = (x_1, x_2, ..., x_n)$ が与えられたとき、ラベル系列 $Y = (y_1, y_2, ..., y_n)$ の条件付き確率を以下のように定義します：

$$
P(Y|X) = \frac{1}{Z(X)} \exp\left(\sum_{i=1}^{n} \sum_{k} \lambda_k f_k(y_{i-1}, y_i, X, i)\right)
$$

ここで：

- $f_k$ は特徴関数（文字の種類、前後の文字など）
- $\lambda_k$ は学習によって決定される重み
- $Z(X)$ は正規化項

つまり、**「この文脈ならこのラベルが来やすい」というパターンを大量のデータから学習**し、新しい入力に対して最適なラベル系列を推論します。

### 3.2 CRFの実用例

CRFは以下のような「系列ラベリング問題」で広く使われています：

1. **固有表現抽出（NER: Named Entity Recognition）**
   - 「東京都に行く」→「東京都」を地名として認識
   - 人名、組織名、日付などを文脈から判定

2. **品詞タグ付け（POS Tagging）**
   - 「走る」が動詞か名詞かを、前後の単語から判定

3. **分かち書き・単語分割**
   - 「すもももももももものうち」→「すもも/も/もも/も/もも/の/うち」
   - 日本語や中国語のように単語間にスペースがない言語で特に有効

4. **音声認識の後処理**
   - 発音が似た単語の文脈による絞り込み

5. **生物情報学**
   - DNAやタンパク質配列の構造予測

### 3.3 点訳へのCRF応用のメリット

#### ① 文脈を考慮した読み推定

```python
# momo.pyの実装例
def char2features(sentence, i):
    features = {
        'char': sentence[i][0],      # 現在の文字
        'type': sentence[i][2],       # 文字種（漢字/かな/数字）
        '-1:char': sentence[i-1][0],  # 前の文字
        '+1:char': sentence[i+1][0],  # 次の文字
        '-1:bi': sentence[i-1][0] + sentence[i][0],  # バイグラム
    }
```

このように、「金星」という単語でも：

- 「横綱に勝つ**金星**」→ 前の文字が「つ」、後ろが句読点 → 「きんぼし」
- 「太陽系の**金星**」→ 前の文字が「の」、周囲に天体用語 → 「きんせい」

という**周辺文脈から適切な読みを推論**できます。

#### ② 分かち書き位置の自動判定

このプロジェクトでは、文字一文字に対して一ブロックの読みを割り当てます。分かち書きは、「この文字の読みの後にスペースを入れるかどうか」というラベルで管理します。
文字を推論するモデルと、分かち書きを推論するモデルを使って、点字を分かち書きを行います。

#### ③ 辞書レスによる軽量化と保守性

| 項目             | 従来の辞書ベース               | CRFアプローチ             |
| ---------------- | ------------------------------ | ------------------------- |
| **データサイズ** | 数十MB〜数百MB（全語彙の辞書） | 5〜15MB（統計モデルのみ） |
| **未知語の扱い** | 辞書にない語は変換不可         | 周囲の文脈から推測可能    |
| **メンテナンス** | 新語のたびに辞書更新が必要     | 訓練データ追加で再学習    |
| **専門知識**     | 辞書作成に職人技が必要         | データさえあれば自動学習  |

当初上記の見積もりでしたが、実際にはもっと多くのメモリーを必要とするようでした。

#### ④ 段階的な精度向上が可能

```python
# 訓練データの追加と再学習が容易
crf.fit(X_train, y_train)  # 新しいデータで再学習
```

- 誤変換の事例を訓練データに追加して再学習するだけで精度向上
- ドメイン特化（医療、法律など）の点訳にも対応しやすい

### 3.4 文脈判断の解像度と「7文字のウィンドウ」

CRFモデルは、現在の実装において最大「前後3文字＋現在の文字」の計7文字を主な判断材料とする**「半径3文字の職人」**としての性質を持ちます。

- **局所的文脈の習得：** 「上手」という表記に対し、直後に「な」があれば「ジョーズ」、2文字前に「舞台」や「客席」があれば「カミテ」と推論するような、隣接語彙との相関に基づく読み分けに極めて強い耐性を持ちます。
- **限界と対策：** 文章の冒頭と結末で意味が繋がるような長距離の依存関係（談話レベルの文脈）の判断は、局所スキャンのみでは困難です。これには「アンカー（錨）」となる単語（例：演劇、能楽など）を意図的に含んだ学習データを増やすことで、統計的な「モード切り替え」をAIに促すアプローチが有効です。

### 3.5 点字論理に基づいた「音節ユニット」の導入

文字単位の処理から、点字の1マス（または接頭符を含むセット）に準拠した**「音節ユニット（Mora-based Unit）」**への転換を図ります。

- **論理的な1:1対応：** 「ッ」や「ー」を独立文字として扱う一方、「ピュ」や「キョ」といった拗音を2文字で1つのユニットとして扱うことで、点字のマス目構成と学習ラベルを完全に同期させます。
- **学習の効率化：** 墨字（普通の文字）の揺らぎに左右されず、点字としての「音の最小単位」で学習を行うため、モデルの収束が早まり、未知語に対する「点字的な推測」の精度が向上します。

## 4. 実現可能な機能

### 1. **文脈に基づく**自動かな変換

テキスト→かな変換を行います。周囲の文脈に応じた読みと分かち書きを推論します。

### 2. 原文と読みの対応関係を保持した**リッチ・トークン**の生成

### 3. 将来的にTTS用、点字用の読み分けに対応

内部的に「リッチ・トークン」を生成し、点字用の読みとTTS用のかな文字列を同時に出力します。「４時」を「４ジ」と「よじ」の両方で出力するなど、用途に応じた柔軟な変換が可能です。

### 4. 点字ディスプレイのためのインデックス情報取得機能

点字ディスプレイのルーティングスイッチに対応するための原文と仮名のインデックス情報を出力します。これにより、エディタなどで、点字ディスプレイのどこをタップしたら原文のどこに対応するか、という双方向のインタラクションが可能になります。

### 5. 環境に合わせた複数のモデルの提供（軽量モデル、精度重視モデルなど）

周囲の文字を考慮するウィンドウサイズや、使用する特徴量の種類を変えた複数のモデルを提供します。これにより、組み込みデバイス向けの軽量モデルと、PC環境で動作する高精度モデルなど、用途に応じた選択が可能になります。
