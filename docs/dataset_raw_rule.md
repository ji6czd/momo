# 点訳データ作成ガイドライン

このドキュメントは、trainer.py` が正しく学習データ（TSV）を生成するための、RAWデータの記述ルールを定めたものです。

## 1. 基本フォーマット

- **ファイル形式**: UTF-8 エンコーディングのテキストファイル。
- **構造**: `原文 [TAB] 読み`
- **区切り文字**: 原文と読みの間は必ず **タブ記号（\t）** で区切ります。
- **読み**: 全角カタカナとASCII文字を仕様。
- ASCIIで表せない記号については、現在未定義。

---

## 2. 書き方の3つのスタイル

`trainer.py` は、原文側の記述形式を自動判別します。

| スタイル          | 原文の書き方 | 読みの書き方 | 特徴                                               |
| ----------------- | ------------ | ------------ | -------------------------------------------------- |
| **① 基本（1:1）** | `自由な`     | `ジ/ユー/ナ` | 1文字ずつ自動対応。最も楽。                        |
| **② グループ化**  | `[今日]は`   | `キョー/ワ`  | 熟字訓や当て字に使用。`[]` 内を1つの塊として扱う。 |
| **③ 厳密指定**    | `平/均`      | `ヘイ/キン`  | スラッシュで明示的に文字の切れ目を指定。           |

---

## 3. 分かち書き（スペース）のルール

点字の分かち書きは、読み側の空ブロック `/ /` を基準に判定されます。

- **記述方法**: `読み側 / /`
- **動作**: その直前の文字ラベルに `+S` フラグを付与します。
- **例**: `前回と異なり` → `ゼン/カイ/ト/ /コト/ナ/リ`
- `ト` のラベルが `ト+S` となり、予測時に後ろにスペースが入ります。

---

## 4. 特殊ラベルの使い分け

### 原文で使用する特殊記号

- **`[]` (角括弧)**: その中の文字を1つのブロックとしてまとめて扱います。熟字訓や当て字に使用します。
- 例: `[今日]は` → `キョー/ワ` （`今日` 全体が1ブロックとして扱われる）

- **`{}` (波括弧)**: その中の文字列が人名であることを示します（詳細は「6. 人名マーク」を参照）。
- 例: `{佐藤}さんだ。` → `サ/トー/ /サ/ン/ダ/。`
- `[]` と違い**ブロック化はしません**。カウントには一切影響せず、読み側は `{}` がないときと同じように書きます。

### 読み側で使用する特殊な記号

- **`_` (アンダースコア)**: その文字に読みを割り当てない（スキップ）場合に、カウント合わせで使用します。
- 例: `二十五 → 2/_/5` （`2` と `5` に読みを割り当て、`25` 全体のブロック数は3でカウントされるため、真ん中の `_` で調整）

- **`---` (トリプルハイフン)**: 読みの継続を示します（通常は原文側で `[]` を使えば自動生成されるため、手動入力は不要です）。

---

## 5. カウント一致の原則（最重要）

`trainer.py` がエラーを出す最大の原因は、**「原文のブロック数」と「読みのラベル数」の不一致**です。

**NG例:** `今日は [TAB] キョー/ワ`

- 原文：`今` `日` `は` （3ブロック）
- 読み：`キョー` `ワ` （2ラベル）
- **解決策:** `[今日]は [TAB] キョー/ワ` （2ブロック : 2ラベルにする）

---

## 6. 人名マーク `{}`

原文側で人名を `{}` で囲むと、`createdata` 実行時に人名辞書
（`person_name_dic.tsv`、TSVと同じディレクトリに自動生成・上書き）へ
**表層形と読み**が登録されます。読みはマーク位置の読み列から自動抽出されるので、
辞書のための追加作業はありません。

- 学習・推論時はこの辞書へのマッチが人名フラグ特徴量（B/I）となり、
  「人名＋敬称の間で区切る」等の分かち書きの汎化を助けます。
- 読みは、推論時に読みモデルが低自信度のときだけ辞書の固定読みで置換する
  フォールバックに使われます（人名の読みは文脈で変化しないため）。
  同じ表層形に複数の読みがマークされていると `createdata` が警告し、
  最頻の読みを採用します。

### 書き方

- **姓と名は別々のスパンで囲みます**。1スパン＝分かち書き1単位＝辞書1エントリです。
- 読み側には何も書きません。分かち書き（`/ /`）と読みは従来通り読み側で与えます。

```text
{佐藤}さんにあった。 [TAB] サ/トー/ /サ/ン/ニ/ /ア/ッ/タ/。
{佐藤}{太郎}くんだ。 [TAB] サ/トー/ /タ/ロー/ /ク/ン/ダ/。
{鈴木}先生と話す。 [TAB] スズ/キ/ /セン/セイ/ト/ /ハナ/ス/。
```

### 判断基準

原則: **「点字の書き方が『人名だから』変わった箇所だけ囲む。迷ったら囲まない。」**

- マークは学習の正解ラベルではなく、辞書登録のための**ヒント**です。
  読みと区切りの正解は、いままで通り読み側の記述だけが決めます。
- したがってマーク漏れは誤りになりません。同じ人名がどこかで1回
  マークされて辞書に載っていれば、マークなしの出現も（読み側が正しい限り）
  整合した学習例として機能します。
- 人名と同じ表層の別語（例:「関係」の「関」、「森林」の「森」、地名の「宮崎」）は
  **囲まずそのまま**残してください。これらは「辞書にマッチしても区切らない」
  反例として学習に役立ちます。

### 注意

- `{}` の閉じ忘れ・空の `{}` は `createdata` がエラーにします。
- マークしただけでは分割されません。読み側に `/ /` がなければ
  人名フラグに正の重みが付かず、効果が出ません。
- 拗音などの複合ユニットの途中でスパンを切ることはできません
  （例: `{さくら}` は可、`{さくらんぼ}` の途中で閉じるのは不可）。

---

## 7. カスタム辞書（--custom-dict）も同じ記法

推論時のカスタム辞書（`momopy predict --custom-dict`）の読み列も、
本ガイドラインと同じ記法で書きます。

```text
電子計算機 [TAB] デン/シ/ケイ/サン/キ      ← 1語指定（内部で区切らない）
佐藤太郎 [TAB] サ/トー/ /タ/ロー           ← 空ブロックの位置で区切る
```

- **エントリ内部の境界は辞書が確定します**: 空ブロック（`/ /`）の位置でだけ
  区切り、それ以外は区切りません。
- **エントリ両端の境界は指定できません**（先頭・末尾の `/ /` はエラー）。
  後ろを区切るかは次に来る語（自立語か付属語か）に依存するため、
  境界モデルが文脈から判定します。

---

## 💡 Tips: 効率的な量産のコツ

1. **まずはベタ打ち**: 原文を書き、読みを `/` で区切って書く。
2. エラーを確認しながら、基本的には原文一文字に一ブロックの読みが対応するように調整する。
3. 熟字訓や当て字は `[]` でまとめる。
4. 分かち書きは 読み側に`/ /` を入れるだけで自動的に学習されます。

## 自動生成

momopyコマンドの predict サブコマンドには、このルールに従った分割をある程度行ってくれる `--segments` オプションを用意しています。原文と読みのカウントは基本的に一致します。分かち書きと読みの間違いを修正することに集中することができます。

```bash
momo predict --segment
```

点字も出力されますから、これを参考にしながら、必要に応じて `[]` や `/` を追加していくと良いでしょう。また、変換ミスもここで修正します。
