# 点訳データ作成ガイドライン

このドキュメントは、trainer.py` が正しく学習データ（TSV）を生成するための、RAWデータの記述ルールを定めたものです。

## 1. 基本フォーマット

* **ファイル形式**: UTF-8 エンコーディングのテキストファイル。
* **構造**: `原文 [TAB] 読み`
* **区切り文字**: 原文と読みの間は必ず **タブ記号（\t）** で区切ります。
* **読み**: 全角カタカナとASCII文字を仕様。
* ASCIIで表せない記号については、現在未定義。

---

## 2. 書き方の3つのスタイル

`trainer.py` は、原文側の記述形式を自動判別します。

| スタイル | 原文の書き方 | 読みの書き方 | 特徴 |
| --- | --- | --- | --- |
| **① 基本（1:1）** | `自由な` | `ジ/ユー/ナ` | 1文字ずつ自動対応。最も楽。 |
| **② グループ化** | `[今日]は` | `キョー/ワ` | 熟字訓や当て字に使用。`[]` 内を1つの塊として扱う。 |
| **③ 厳密指定** | `平/均` | `ヘイ/キン` | スラッシュで明示的に文字の切れ目を指定。 |

---

## 3. 分かち書き（スペース）のルール

点字の分かち書きは、読み側の空ブロック `/ /` を基準に判定されます。

* **記述方法**: `読み側 / /`
* **動作**: その直前の文字ラベルに `+S` フラグを付与します。
* **例**: `前回と異なり` → `ゼン/カイ/ト/ /コト/ナ/リ`
* `ト` のラベルが `ト+S` となり、予測時に後ろにスペースが入ります。

---

## 4. 特殊ラベルの使い分け

### 原文で使用する特殊記号

* **`[]` (角括弧)**: その中の文字を1つのブロックとしてまとめて扱います。熟字訓や当て字に使用します。
* 例: `[今日]は` → `キョー/ワ` （`今日` 全体が1ブロックとして扱われる）

### 読み側で使用する特殊な記号

* **`_` (アンダースコア)**: その文字に読みを割り当てない（スキップ）場合に、カウント合わせで使用します。
* 例: `二十五 → `2/_/5` （`2` と `5` に読みを割り当て、`25` 全体のブロック数は3でカウントされるため、真ん中の `_` で調整）

* **`---` (トリプルハイフン)**: 読みの継続を示します（通常は原文側で `[]` を使えば自動生成されるため、手動入力は不要です）。

---

## 5. カウント一致の原則（最重要）

`trainer.py` がエラーを出す最大の原因は、**「原文のブロック数」と「読みのラベル数」の不一致**です。

**NG例:** `今日は [TAB] キョー/ワ`
* 原文：`今` `日` `は` （3ブロック）
* 読み：`キョー` `ワ` （2ラベル）
* **解決策:** `[今日]は [TAB] キョー/ワ` （2ブロック : 2ラベルにする）

---

## 💡 Tips: 効率的な量産のコツ

1. **まずはベタ打ち**: 原文を書き、読みを `/` で区切って書く。
2. エラーを確認しながら、基本的には原文一文字に一ブロックの読みが対応するように調整する。
3. 熟字訓や当て字は `[]` でまとめる。
4. 分かち書きは 読み側に`/ /` を入れるだけで自動的に学習されます。

## 自動生成

momoコマンドのSudachi変換には、このルールに従った分割をある程度行ってくれる `-s` オプションを用意しています。完全ではないため、細かい調整は手動で行う必要がありますが、基本的な分割は自動で行われるため、量産の効率が大幅に向上します。

```
momo translate -s
```

点字も出力されますから、これを参考にしながら、必要に応じて `[]` や `/` を追加していくと良いでしょう。また、変換ミスもここで修正します。
