# UEB Grade 2 仕様書 — Phase 6「約物・記号と語境界の規範化」

Phase 1〜5 で縮約体系は揃った。Phase 6 は**縮約の外側**——約物・記号・語境界・grade 1 モード——を
埋めて、英文を UEB で書ききれるようにする。

**出典が手に入った**ことが Phase 6 の最大の変化。Phase 1〜5 は EBAE の知識と二次資料からの
再構成だったが、Phase 6 は ICEB の規範そのものを引いている：

- [The Rules of Unified English Braille, Third Edition 2024](https://iceb.org/wp-content/uploads/2025/10/Rules-of-Unified-English-Braille-2024.pdf)（408ページ）
- [UEB List of Punctuation（Section 7 の一覧）](https://uebot.niu.edu/courses/pluginfile.php/96/block_html/content/UEB%20List%20of%20Punctuation.pdf)

---

## 1. 約物・記号（§7 / §3）

`[punctuation]` を8種から**48種**へ拡張した（`english_ueb_grade2.toml` / `english_ueb_grade1.toml`
の両方。インベントリは grade で変わらない）。

| 種別 | 追加したもの |
|---|---|
| 括弧 | `( ) ⠐⠣ ⠐⠜` / `[ ] ⠨⠣ ⠨⠜` / `{ } ⠸⠣ ⠸⠜` / `< > ⠈⠣ ⠈⠜` |
| ダッシュ類 | en dash `–` ⠠⠤ / em dash `—` ⠐⠠⠤ / 下線 `_` ⠨⠤ / 省略記号 `…` ⠲⠲⠲ |
| スラッシュ | `/` ⠸⠌ / `\` ⠸⠡ |
| 記号 | `@ & * # • ^ ~ % ° © ® ™ § ¶` |
| 通貨 | `$ ¢ € £ ¥` |
| 演算・比較 | `+ = × ÷ −` |

**引用符は別セクション** `[quotes]` にした。開きと閉じでセルが違うからで、1対1のマップに収まらない。

```toml
[quotes]
"\"" = { open = "⠦", close = "⠴" }   # 非特定引用符（規範の用例が二重引用符にこれを使う）
"‘"  = { open = "⠠⠦", close = "⠠⠴" } # 一重引用符
```

開き／閉じは**文脈で決める**（直前が空白・行頭・開き括弧なら開き）。アポストロフィ `'` は
引用符ではなく約物 ⠄ のまま（`it's` = `⠭⠄⠎`）。

## 2. standing alone の規範化（§2.6）— Phase 5 の近似を差し替え

Phase 5 は「前後が空白・行頭行末・約物」と近似していたが、規範はもっと厳密だった。

- **§2.6.1**: standing alone とは、**空白・ハイフン・ダッシュ**に前後を挟まれること。
- **§2.6.2/§2.6.3**: 決められた約物の介在だけが許される。
  - 前: 開き括弧・開き引用符・非方向引用符・アポストロフィ・大文字符
  - 後: コンマ・セミコロン・コロン・終止符・省略記号・`!`・`?`・閉じ括弧・閉じ引用符・アポストロフィ
- したがって**スラッシュや数字や `@` は語境界にならない**。`could/should` は縮約されず
  `⠉⠳⠇⠙⠸⠌⠩⠳⠇⠙`（groupsign の `ou` だけ使う）、`but...not` は `⠃⠥⠞⠲⠲⠲⠝⠕⠞`。
- **§2.6.4**: 語中アポストロフィを持つ語（`it's` / `wouldn't`）は**並び全体で1語**とみなす。
  縮約は先頭の文字列にだけ効く（`it's` = `⠭⠄⠎`。末尾の `s` は縮約対象にならない）。

Phase 5 の「数字は語境界ではない」（`4th` の `th` は wordsign にならない）はこの規範の帰結として
正しかった。規範の用例 `7(b)` = `⠼⠛⠐⠣⠃⠐⠜` が裏づけになる（`b` は数字に続くので単独ではなく、
「but」と読まれる恐れがないので grade 1 記号符も要らない）。

## 3. shortform も standing alone を要求する（§10.9.1 / §10.9.2）

Phase 4b は「語が Appendix 1 のリストにあれば語中どこでも使える」としていたが、規範は
**その語自身が standing alone であること**も要求していた。`could/should` が縮約されないのはこれ。

あわせて**データの穴**が見つかった: Appendix 1 は `wouldn't` `could've` `'twould` のような
**アポストロフィ付きの語もリストに載せている**。以前の抽出は a–z だけを拾っていて18語を落としていた。
追加した結果 `wouldn't` = `⠺⠙⠝⠄⠞`（`would`→`wd` + `n` + `'t`）が規範どおりになる。
shortform の可否判定は、英字の連なりではなく**アポストロフィで繋がった並び全体**で行う。

---

## 4. grade 1 記号符の一般化（§5.7 / §10.9.7）

Phase 5 は「数符直後の a–j」だけだったが、規範はもっと一般的だった：
**単独で立つ文字列が縮約として読めてしまうなら grade 1 記号符 ⠰ を前置する。**

- `b` → `⠰⠃`（⠃ は「but」）、`ab` → `⠰⠁⠃`（⠁⠃ は shortform「about」）、`CD` → `⠰⠠⠠⠉⠙`（「could」）
- `a` / `i` / `o` は縮約セルを持たないので不要（規範の Note と一致）
- 大文字符より**前**に置く（`X` → `⠰⠠⠭`）

実装は**データを増やさずに導ける**: 縮約テーブルから「語全体として使えるセル列 → 綴り」の
逆引きを作り、単独語の出力セル列がそこに一致して綴りが違えば前置する。

**数値モード（§6.2）も規範に合わせた**。数値モードは小数点・桁区切りを跨いで続くので、
`take2.com` は `⠞⠁⠅⠑⠼⠃⠲⠰⠉⠕⠍`（`.` の後も数値モードで、`c` に grade 1 記号符が要る）。

## 5. 検証（2026-07-13）

規範の本文から**用例45件**をそのまま取って回帰テストにした（`rules_of_ueb_examples`）。
§2.6 の standing alone、§5.2 の grade 1、§6 の数値モード、§7 の約物、§10.9 の shortform を横断する。
**45件すべて一致**。Phase 6 の作業中、この45件が3つの実装の誤りを暴いた:

1. shortform に standing alone を要求していなかった（`could/should`）
2. Appendix 1 のアポストロフィ付き語を落としていた（`wouldn't`）
3. 数値モードが小数点で切れていた（`take2.com`）

テストは momors-braille 全体で 219 件。
