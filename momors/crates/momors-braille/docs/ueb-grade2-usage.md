## 2. 縮約の選択＝セル数最小化

**規範**: 選択の余地があるときは、**最も多くのセルを節約する縮約**を使う。

Phase 1〜4 の実装は「左→右・綴りの最長一致（貪欲）」で近似していた。綴りの長さとセル数は
比例しないので（頭字符は2セルで4〜8文字、下方 groupsign は1セルで2〜3文字）、貪欲は最適とは限らない。

**実装**: 語 `[start, end)` を**動的計画法**で分割し、**総セル数が最小**になる分割を選ぶ。

```text
best[i] = min over 「位置 i で適用可能な縮約 c（および1文字）」 of
            cells(c) + best[i + len(c)]
best[end] = 0
```

- `cells(c)` = 縮約セル列の長さ（1 または 2、shortform は 2〜5）。
- **同数のときは綴りの長い方**（＝左の位置でより多くの文字を1つの選択にまとめる方）を採る。
  規範の tie-break「発音をよく表す方」は綴りから決まらないので、この近似を採る。
- 適用可能性（`applicable`）は位置 `i`・長さ `len`・語境界・語そのものだけで決まり、
  **他の分割に依存しない**。ゆえに DP が正しく最適解を返す（部分構造最適性が成り立つ）。

計算量は `語長 × 最長縮約長(10)` で、実質定数。

## 3. 形態素境界を跨ぐ縮約の抑制

**規範**: 語構成（接頭辞＋語根、語根＋語根）の境界を跨ぐ縮約は使わない。
`mishap` = `mis`+`hap` の `sh` は縮約しない（`⠍⠊⠎⠓⠁⠏`）。

境界の判定には**語彙知識が要る**（綴りからは決まらない。`mishap` は割れるが `mishmash` は割れない）。
[[project-liblouis-integration]] で見たとおり、これは**必然的複雑さ**であって、記法では消せない。
そこで [[feedback-data-driven-uniform-types]] と Phase 2b の `initial_stems` と同じ方針を採る：

**データで足す。既定は現状どおり縮約する（＝リストに無い語は Phase 4 までと同じ出力）。**
リストを増やすほど正しくなり、リストが間違っていない限り出力は壊れない。

### データ形式

```toml
[morphemes]
# `|` が形態素境界。ここを跨ぐ縮約を使わない。1語に複数の境界を書ける。
boundaries = [
  "mis|hap",     # sh を跨がせない → ⠍⠊⠎⠓⠁⠏
  "hot|house",   # th
  "fog|horn",    # gh
  "co|worker",   # ow
]
```

### 適用規則

- 語（小文字化）がリストに一致したら、その境界オフセット集合 `B` を得る。
- 位置 `i`・長さ `len` の縮約は、`i < b < i+len` なる `b ∈ B` があれば**不適用**。
  境界にちょうど接する縮約（`i+len == b` や `i == b`）は使える（`with|hold` の `with` は可）。
- **屈折語尾の吸収**: 語がリストに無いとき、末尾の `s` / `es` / `ed` / `ing` / `ly` を落として再照合する。
  境界オフセットは語幹側にあるのでそのまま使える（`mishaps` → `mishap` の境界を適用）。

### 初期リスト

sh / th / gh / ow / wh が語根の切れ目を跨ぐ代表語を種として入れる（§7 で要レビュー）。
リストは**増やすためのもの**であって、完全性を主張しない。

## 4. standing alone（単独で1語）の厳密化

**規範（§2.6）**: 語が standing alone であるとは、前後が**空白・行頭行末・約物**であること。
wordsign（アルファベット/強/下方）と shortform（Phase 4a）はここでだけ使える。

これまでの実装は「英字の連続＝語」だけを見ており、隣が**数字**でも単独扱いになっていた。

- **数字は語境界ではない**。`4th` の `th` は standing alone でないので **wordsign `this` にならない**
  （Phase 4 までは `⠼⠙⠹` が「this」の意味で出ていた）。
- **約物は語境界**。アポストロフィ・ハイフンを含む（`it's` の `it` は単独＝`⠭⠄⠎`、
  `can-do` の `can` は単独＝`⠉⠤⠙⠕`）。これは英字連続を語とする現状の挙動と一致するので、
  **規則として明文化しテストで固定する**のが Phase 5 の仕事。

実装は `standing_alone` フラグを語ごとに立て、`Position::Wordsign` の判定に AND する
（shortform の Phase 4b 経路＝語中適用はこのフラグに依存しない）。

## 5. grade 1 指示符（数字直後の a–j）

**規範（§6）**: 数符（`⠼`）で始まる numeric mode 中、`a`–`j` は数字 `1`–`0` と同じセルなので、
数字の直後に `a`–`j` が続くときは **grade 1 記号符 `⠰`（56）** を前置して文字であることを示す。

- `1a` → `⠼⠁⠰⠁`（`⠼⠁⠁` では `11` と読めてしまう）。
- `4th` → `⠼⠙…`（`t` は a–j でないので指示符は不要）。
- **大文字符が挟まるなら不要**（`⠠` は数字セルではないので曖昧性が消える）。`4A` → `⠼⠙⠠⠁`。

データ: `[indicators] grade1 = "⠰"` を追加する（grade 1 テーブルにも同じ指示符を置く）。

---

## 6. 語中の散在大文字

**規範（§4）**: 大文字符 `⠠` は次の1文字を、大文字語符 `⠠⠠` は語全体を大文字にする。

これまでは「語頭のみ大文字」「語全体が大文字」の2形だけだった。Phase 5 では
**大文字で始まる各セルの直前に大文字符を置く**規則に一般化する（語全体が大文字なら `⠠⠠` 1つ）。

- `McDonald` → `⠠⠍⠉⠠⠙…`（`M` と `D` にそれぞれ大文字符）。
- 語全体大文字（2文字以上）は従来どおり `⠠⠠` 1つ。
- **割り切り**: 縮約セルの途中に大文字が来る場合（`iPhone` の `Ph` を `ph` として縮約する等）は
  セル先頭の大文字だけを見る。語中の大文字連続に対する大文字語符＋終止符（`⠠⠄`）は使わない。

また `greathearted` が `great|heart` を跨いで `the` を縮約していたのが見つかり、境界リストへ追加した。

## 6c. 【追記 2026-07-13】§7 の要確認は Phase 6 で原典により解決した

出典 PDF（Rules of UEB 2024）が入手できたので、下の §7 の宿題は規範で決着した。
詳細は `ueb-grade2-punctuation.md`（Phase 6）。

1. **`4th` の `th`**: groupsign は使う（`⠼⠙⠹`）。数字は語境界ではないので wordsign にはならない。
   規範の `7(b)` = `⠼⠛⠐⠣⠃⠐⠜` が裏づけ。
2. **standing alone の定義**: §2.6 の規範（空白・ハイフン・ダッシュ＋許される約物の介在）に
   置き換えた。スラッシュは語境界にならない（`could/should` は縮約しない）。
3. **ハイフン結合語で wordsign**: 正しい（`can-do` = `⠉⠤⠙`。§2.6.1 がハイフンを明示）。
4. **grade 1 記号符**: 「数符直後の a–j」は規範の特例で、一般規則は §5.7（単独語が縮約として
   読めるなら前置）。Phase 6 で一般化した。

## 7. 要確認（当時の宿題。§6c で解決済み）

1. **`4th` / `14th` で `th` の groupsign を使うか**。Phase 5 は「wordsign は不可（standing alone でない）、
   groupsign は使う」＝`⠼⠙⠹` とした。数字に接する縮約を一切使わない規範があるなら直す。

3. **ハイフン結合語で wordsign を使う**（`can-do` の `can` → `⠉`）で正しいか。

## 8. Phase 5 で残らない／残るもの

**解消**: 縮約の選択（最長一致→セル数最小）、形態素境界（データで抑制可能に）、
standing alone の定義、grade 1 指示符、語中の散在大文字。

**残る（grade 2 の外）**: 発音依存の tie-break、大文字終止符 `⠠⠄`、
grade 1 語符・句符（`⠰⠰` / `⠰⠰⠰`）、書式（行取り・見出し）、英語の**逆変換**（点字→英文）。
